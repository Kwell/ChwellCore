# MySQL 会话所有权与写入 fencing

`cluster::MysqlSessionStore` 是可选真实 MySQL 后端（`CHWELL_USE_MYSQL=ON`）。
它将玩家租约和受保护文档放在同一数据库、同一连接的 InnoDB 事务中，避免外部锁检查
通过后、文档写入前会话已换主的竞态。实现独立编写，未复制 ARK 源码。
`SessionLocator` 仍是进程内路由索引，不能充当全局写入授权。

## 契约

租约包含 player、owner、node、incarnation、epoch。player 是 1–64 字节，其他身份是
1–128 字节；epoch 用十进制字符串传输，保留 unsigned BIGINT 精度。
owner 必须标识网关进程和连接，incarnation 必须标识 Game 的本次进程生命周期。
同一玩家同时只能有一个有效租约。示例采用每次启动随机进程身份，客户端不能指定这些字段。

| 操作 | 语义 |
| --- | --- |
| acquire | 锁定玩家行；有效旧租约返回 Busy；失效或释放后递增 epoch 并绑定新身份 |
| renew | 锁定并检查全部身份及数据库当前时间；已过期租约不能复活 |
| release | 检查全部身份后清空 owner；即使已过期也可释放，旧 epoch 不能影响新持有者 |
| lookup | 诊断查询；结果不是执行后续写入的授权 |
| apply | 锁定租约，校验身份/期限，在同一连接执行文档读写，再检查期限并提交 |

租约记录永久保留，释放不删除，epoch 溢出时拒绝 acquire。删除行、回滚数据库到旧快照
会破坏单调性，禁止在服务运行时清理该表。锁等待结束后另起查询使用新数据库时间，
避免 MySQL `NOW()` 固定为语句开始时间而错误地续租过期记录。

`apply` 回调只允许在提供的 StorageInterface 上 get/put/remove。禁止改变连接、事务，
禁止嵌套调用会话存储，禁止网络 I/O、发送客户端包或其他不可回滚副作用。
返回失败或抛异常会回滚，异常继续向调用方传播；执行中租约过期也回滚。
必须在 apply 成功返回后发布已暂存的同步结果。事务持有玩家租约行锁，新的 acquire/
renew/release/apply 等待该锁；不会出现旧事务越过已提交的新所有权继续写入。
该锁只保护对应 player；跨玩家转账、多实体事务需要另行设计锁顺序和所有权协议。
后台任务/管理端若绕过 apply 直接写相同文档，不受此保护。

## 状态与恢复

- Ok：提交确认成功；Busy：已有有效持有者；Lost：身份不匹配、已释放或已过期。
- Invalid：参数非法或回调拒绝；回调错误保留在 error 中，当前事务回滚。
- Unavailable：连接/SQL/回滚失败；断开连接，后续独立调用重新建连，当前工作不重放。
- Unknown：COMMIT 回应失败，提交结果无法确定。断开连接，必须读取确认，不能盲目重放。

`connect`、会话操作和回调均阻塞。连接生命周期和整个事务在实例内串行；不同实例通过
数据库行锁协调。关闭 MySQL 自动重连，锁等待上限为 2 秒；调用方配置连接及读写超时。
这不保证完整请求总时限或高并发吞吐，也未实现幂等请求日志。

参考工程每个网关持有独立权威存储连接，租约 TTL=8 秒，每 2 秒续租。
发现失败、节点/进程变化、续租或存储错误会撤销本地会话，释放精确身份的租约；释放失败
等待数据库期限到期。网关异常退出不恢复 TCP 会话，另一网关在过期后重新登录。
Game 的每次请求（含读取、登录建档和 advance）都检查租约和自身进程标识。
业务失败、响应丢失不会自动重试；成功 advance 的 read-modify-write 与 fencing 原子提交。

## 数据库条件与已有数据升级

同一 MySQL 主库是权威，使用其时钟判定租约。依赖 InnoDB 行锁、事务和主库已提交数据的
持久性；不保证异步复制丢数据、主库脑裂、时钟大幅回拨或灾难备份回滚后的正确 fencing。
业务文档必须使用这个事务连接访问同一数据库。当前没有 Redis/MySQL 双权威机制。

新 MysqlStorage 键表使用 `utf8mb4_bin` 区分大小写；租约 player 为 VARBINARY。
会话存储启动验证两个表的 InnoDB 引擎及文档键列的 `utf8mb4_bin`，不满足则失败，
不会自动修改已有业务表。示例 player 只接受 ASCII 字母、数字、下划线、连字符，避免
VARCHAR 的尾部空格等键规范化差异。通用调用方必须保证 player 到业务键一一对应。

从上一版参考工程升级时，停止所有写入、备份并核对业务键，再执行：

```sql
ALTER TABLE cluster_kv ENGINE=InnoDB;
ALTER TABLE cluster_kv MODIFY k VARCHAR(512) CHARACTER SET utf8mb4 COLLATE utf8mb4_bin NOT NULL;
```

旧的不区分大小写表中曾覆盖的记录不会被这条 DDL 恢复。不要同时运行旧版绕过 fencing 的
Game。租约表由新版自动创建；已有租约表也必须保留正确结构和 epoch。

## 验证

CI 在 ASan/UBSan 下运行真实 MySQL 两连接契约：全局抢占冲突、递增 epoch、旧身份拒绝、
回调失败/异常回滚、并发增量无丢失、执行中过期回滚、锁等待后禁止复活，以及重建连接。
真实 TCP 双网关测试覆盖同时登录、SIGSTOP 持有者过期接管、旧 RPC/续租/释放、Game 沿用
同一 generation 参数重启、网关被杀后的恢复，并用独立 SQL 查询验证旧请求没有修改数据。
Compose 同时启动两个网关；原有真实存储/注册中心故障、权限同步和卷恢复测试继续执行。
